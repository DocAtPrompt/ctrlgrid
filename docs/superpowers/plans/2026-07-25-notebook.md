# `notebook` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One linked PDF of sections, each filled by an existing blade — `notebook` as the second document generator, and the first that composes blades.

**Architecture:** The page *describes*, the handle *fills*. `DocumentPage` gains an optional `Fill` (a generator name plus its validated config); one function in `pages.py` says what is on a page — its own marks, then its fill's — and the writer, the capability pre-flight and the media check all call it. The notebook never touches a blade. Document bands become per page so `{page}` and a new per-page `{section}` mean something.

**Tech Stack:** Python 3.11+, pydantic v2 (a section validates its blade's keys through that blade's own `config_model`, with the loader's validation context so `px` and `%w` still resolve), integer micrometres, `pytest`, `ruff`.

**Design:** [`2026-07-25-notebook-design.md`](../specs/2026-07-25-notebook-design.md) — read it first; it carries the rejected alternatives.

```python
@dataclass(frozen=True, slots=True)
class Fill:
    """A page a blade fills (§ 7.13). The document names the generator and the
    config it already validated; the handle calls it, exactly as it calls a
    blade on the ordinary page path — the notebook never touches one."""

    generator: str
    config: Any
```

  and in `pages.py`:

```python
def document_page_marks(page: DocumentPage, *, area: Area, context: PageContext, q):
    """What is on one document page: its own marks, then its fill's (§ 7.13).

    One function, because three callers ask the question — the writer, the
    capability pre-flight and the media check — and three answers would drift.
    """
    yield from page.marks
    if page.fill is not None:
        from ctrlgrid import generators

        blade = generators.get(page.fill.generator)
        yield from blade.generate(page.fill.config, area=area, page=context, q=q)
```

  Then route `_build_document`, `_refuse_writer_cannot_render_document` and `media._document_sample` through it.

### Task 3: the `notebook` generator

**Files:** `ctrlgrid/generators/notebook.py` (new), `ctrlgrid/generators/__init__.py`, `tests/test_notebook.py` (new)

- [ ] **Step 1** — failing tests for the config: a section validates its blade's own keys through that blade's model (a typo names the blade); an unknown generator lists the known ones; a *document* generator in a section is refused by name; `pages: 0` and an empty `sections:` are errors; a section whose blade `check` refuses stops the run with that blade's message.
- [ ] **Step 2** — implement the config. The fiddly part is that a section is a small definition, so the blade's keys arrive beside the section's own and are moved out before validation:

```python
_SECTION_KEYS = ("label", "pages", "divider", "generator")


class NotebookSection(Section):
    """One run of pages filled by one blade (§ 7.13)."""

    label: str | None = None
    pages: int = Field(ge=1)
    divider: bool = False
    generator: str
    config: Any = None   # the blade's own section, validated below

    @model_validator(mode="before")
    @classmethod
    def _the_blade_validates_its_own_keys(cls, data, info):
        if not isinstance(data, dict):
            return data
        from ctrlgrid import generators
        from ctrlgrid.document import is_document_generator

        own = {k: v for k, v in data.items() if k not in (*_SECTION_KEYS, "config")}
        kept = {k: v for k, v in data.items() if k in _SECTION_KEYS}
        blade = generators.get(kept.get("generator"))    # raises, listing the known ones
        if is_document_generator(blade):
            raise ValueError(
                f"`{blade.name}` owns its own pages, so it cannot fill a section of a "
                "notebook — a section is pages, and a document generator is what "
                "produces them (§ 7.13)"
            )
        # The same validation context the loader gives the top-level blade, so
        # `px` and `%w` resolve in a section exactly as they do in a definition.
        kept["config"] = blade.config_model.model_validate(own, context=info.context)
        return kept
```

  `NotebookConfig` holds `sections: tuple[NotebookSection, ...] = Field(min_length=1)`, an optional `title_page` and an optional `contents_title`. `check` loops the sections and calls each blade's `check(section.config, area=area, q=q)`.
